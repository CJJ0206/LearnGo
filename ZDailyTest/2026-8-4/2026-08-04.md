## 一、闭包（下）

**1.** 写一个 `MakeSuffix` 函数，接收文件后缀名（如 `.jpg`），返回一个闭包。闭包接收文件名，如果文件名已有该后缀则直接返回，没有则加上后缀。

<details><summary>答案</summary>

```go
func MakeSuffix(suffix string) func(string) string {
    return func(name string) string {
        if !strings.HasSuffix(name, suffix) {
            return name + suffix
        }
        return name
    }
}
```

使用：
```go
f := MakeSuffix(".jpg")
f("photo")     // "photo.jpg"
f("cat.jpg")   // "cat.jpg"
```

</details>

---

**2.** 以下两个闭包函数有什么本质区别？哪个更通用？

```go
// A
func MakeSuffix(suffix string) func(string) string { ... }

// B
func MakeJpgSuffix() func(string) string {
    suffix := ".jpg"
    return func(name string) string { ... }
}
```

<details><summary>答案</summary>

A 更通用。A 通过参数传入 `suffix`，可以处理任意后缀名（`.png`、`.txt` 等）。B 把后缀写死为 `.jpg`，只能处理一种后缀。

闭包中绑定的外部变量来源不同：A 来自函数参数，B 来自函数内部局部变量。

</details>

---

**3.** 写一个闭包计数器 `NewCounter`，每次调用返回递增的值（从 1 开始）。

<details><summary>答案</summary>

```go
func NewCounter() func() int {
    i := 0
    return func() int {
        i++
        return i
    }
}

// 使用
c := NewCounter()
c()  // 1
c()  // 2
c()  // 3
```

</details>

---

**4.** 闭包中的变量 `i` 是隔离的吗？创建两个独立的计数器会互相影响吗？

<details><summary>答案</summary>

**不会互相影响。** 每次调用 `NewCounter()` 都会创建一个新的闭包实例，每个实例有自己的 `i` 变量。两个计数器是完全独立的：

```go
c1 := NewCounter()  // c1 有自己的 i
c2 := NewCounter()  // c2 有自己的 i
c1()  // 1
c2()  // 1  ← 不会受 c1 影响
```

</details>

## 二、defer 延迟机制

**5.** 以下代码的输出顺序是什么？为什么？

```go
func Sum(n1, n2 int) int {
    defer fmt.Println("ok1 n1 =", n1)
    defer fmt.Println("ok2 n2 =", n2)
    res := n1 + n2
    fmt.Println("ok3 res =", res)
    return res
}
Sum(10, 20)
```

<details><summary>答案</summary>

```
ok3 res = 30
ok2 n2 = 20
ok1 n1 = 10
```

defer 将语句压入一个独立的栈（先入后出），函数执行完毕后才从栈中依次出栈执行。所以 `defer ok1` 最先入栈，最后执行；`defer ok2` 后入栈，先执行。

</details>

---

**6.** defer 的主要使用场景有哪些？

<details><summary>答案</summary>

1. **释放资源**：关闭文件、数据库连接、网络连接
2. **解锁互斥锁**：`mu.Lock()` 后 `defer mu.Unlock()`
3. **捕获 panic**：配合 `recover()` 做异常恢复
4. **记录函数执行时间**：`defer time.Since(time.Now())`

</details>

**7.** defer 将语句入栈时，参数的值是"快照"还是"最新值"？

```go
func Sum2(n1, n2 int) int {
    defer fmt.Println("ok1 n1 =", n1)  // 输出什么？
    defer fmt.Println("ok2 n2 =", n2)  // 输出什么？
    n1++
    n2++
    res := n1 + n2
    fmt.Println("ok3 res =", res)  // 输出什么？
    return res
}
Sum2(10, 20)
```

<details><summary>答案</summary>

```
ok3 res = 32
ok2 n2 = 20
ok1 n1 = 10
```

defer 将语句入栈时，**同时拷贝了相关变量的值**（值快照）。即使后续 `n1++`、`n2++`，defer 中输出的仍然是入栈时的值 10 和 20。

但 `res` 的计算用的是修改后的值：`(10+1) + (20+1) = 32`。

</details>

**9.** 值传递和引用传递的本质区别是什么？它们都是"拷贝"吗？

<details><summary>答案</summary>

**都是拷贝**，但拷贝的内容不同：

- **值传递**：拷贝的是数据的完整副本，修改副本不影响原值
- **引用传递**：拷贝的是**地址的副本**，但通过地址可以访问和修改同一块数据

引用传递效率通常更高，因为只拷贝一个地址（8 字节），而不是拷贝整个大数据结构。

</details>

---

**10.** 在函数参数中，`*T` 类型的参数是什么传递？为什么传结构体地址比传整个结构体效率高？

<details><summary>答案</summary>

`*T` 类型的参数是**值传递**（传递的是地址副本），但效果上等同于引用传递——因为通过地址可以修改原始数据。

传地址效率高：指针只有 8 字节（64位系统），而结构体可能有几十个字段、几百字节。拷贝一个 8 字节地址比拷贝整个结构体快得多。

</details>

## 四、变量作用域

**11.** 以下代码输出什么？解释"就近原则"。

```go
var Name = "cjj"

func Test01() { fmt.Println(Name) }
func Test02() {
    Name := "jack"
    fmt.Println(Name)
}
func Test03() { fmt.Println(Name) }

Test01()
Test02()
Test03()
```

<details><summary>答案</summary>

```
cjj
jack
cjj
```

`Test02` 中用 `:=` 声明了局部变量 `Name`，根据**就近原则**，函数内优先使用局部变量，所以打印 `"jack"`。`Test01` 和 `Test03` 没有局部变量，使用包级全局变量 `"cjj"`。

</details>

---

**12.** 以下代码有什么问题？

```go
var Name = "cjj"
func Test04() {
    Name = "jack"
}
Test04()
fmt.Println(Name)
```

<details><summary>答案</summary>

代码本身没有语法错误，但 `Test04` 中 `Name = "jack"`（用的是 `=` 不是 `:=`），**修改的是全局变量**。所以 `fmt.Println(Name)` 输出 `"jack"`。

如果意图是创建局部变量但误写成了 `=` 而非 `:=`，就是一个 bug——悄悄修改了全局状态。

</details>

---

**13.** 函数体外 `a := 55` 能编译吗？为什么？

<details><summary>答案</summary>

**不能。** 函数体外部的任何代码语句，都必须以 Go 语言的关键字开头（如 `var`、`func`、`type`、`const`、`import`）。`:=` 不是关键字，所以不能在包级别使用。

正确写法：`var a int = 55` 或 `var a = 55`。

</details>
