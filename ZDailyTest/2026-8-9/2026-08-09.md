## 一、切片基础概念

**1.** 切片在 64 位架构下，内存中固定占用多少字节？由哪三个字段组成？

<details><summary>答案</summary>

切片固定占用 **24 字节**，由三个 8 字节字段组成：

```go
type slice struct {
    array unsafe.Pointer // 指向底层数组的指针 (8 bytes)
    len   int            // 切片的当前长度 (8 bytes)
    cap   int            // 切片的容量 (8 bytes)
}
```

</details>

---

**2.** 切片和数组在定义语法上唯一的区别是什么？

<details><summary>答案</summary>

**中括号里有没有数字（长度）**：

```go
var arr [5]int  // 数组：指定了长度
var s []int     // 切片：没有长度
```

</details>

---

**3.** 以下代码中 `len(slice)` 和 `cap(slice)` 分别是多少？为什么？

```go
var intArr = [5]int{1, 2, 3, 4, 5}
slice := intArr[1:3]
```

<details><summary>答案</summary>

- `len(slice)` → **2**（元素个数：索引 1、2）
- `cap(slice)` → **4**（从切片起始位置到数组末尾：索引 1,2,3,4 共 4 个位置）

公式：`cap = 底层数组长度 - 切片起始索引`

</details>

## 二、切片的三种创建方式

**4.** 写出切片创建的三种方式，并各给一个示例。

<details><summary>答案</summary>

```go
// 方式一：引用已有数组
var arr = [5]int{1, 2, 3, 4, 5}
slice1 := arr[2:5]

// 方式二：make 创建
slice2 := make([]int, 4)       // len=4, cap=4
slice3 := make([]int, 4, 10)   // len=4, cap=10

// 方式三：直接指定元素
slice4 := []int{1, 2, 3}
```

</details>

---

**5.** `make([]int, 4)` 和 `make([]int, 4, 10)` 有什么区别？如果不指定 cap，cap 默认是多少？

<details><summary>答案</summary>

- `make([]int, 4)`：len=4, cap=4（默认 cap = len）
- `make([]int, 4, 10)`：len=4, cap=10（预留了额外容量）

不指定 cap 时，**cap 默认等于 len**。

</details>

---

**6.** 通过 `make` 创建的切片和通过引用数组创建的切片，在内存布局上有什么关键区别？

<details><summary>答案</summary>

- **引用数组创建**：切片和原数组**共享底层数据**，修改切片会影响原数组，存在数据暴露风险
- **make 创建**：切片指向一个**不暴露的、独立的内存地址**，与外部隔离，更安全

</details>

## 三、切片的引用传递

**7.** 以下代码输出什么？为什么？

```go
arr := [5]int{1, 2, 3, 4, 5}
slice := arr[:]
slice2 := slice
slice2[0] = 520
slice[1] = 250
arr[2] = 125
fmt.Println(slice)
fmt.Println(slice2)
fmt.Println(arr)
```

<details><summary>答案</summary>

三个输出都是 `[520 250 125 4 5]`。

**原因**：切片是引用类型，`slice`、`slice2`、`arr` 三者指向同一块底层数组。修改任意一个，所有引用都能看到变化。

</details>

---

**8.** 切片传给函数后，函数内修改切片元素，会影响原切片吗？为什么？

<details><summary>答案</summary>

**会影响。** 切片是引用类型，传递时拷贝的是 slice header（24 字节），但 header 中的指针仍指向同一块底层数组。所以函数内修改元素，原切片也会变。

</details>

## 四、append 底层原理

**9.** `append` 的返回值必须赋值回原切片变量吗？以下代码有什么问题？

```go
var s = []int{1, 2, 3}
append(s, 4)
fmt.Println(s)
```

<details><summary>答案</summary>

**必须赋值回去。** 上面的代码输出 `[1 2 3]`，4 没有被加上。

正确写法：
```go
s = append(s, 4)
```

原因：append 可能扩容并创建新数组，如果不接收返回值，原切片变量仍指向旧数组。

</details>

---

**10.** 描述 append 在**超过容量**和**仍在容量内**两种情况下，底层分别做了什么？

<details><summary>答案</summary>

| 情况 | 底层行为 |
|------|---------|
| **超过容量** | ① 创建更大的新数组 ② 拷贝旧数据到新数组 ③ 写入新元素 ④ 返回指向新数组的切片（指针变了） |
| **仍在容量内** | 直接在底层数组的 len 位置写入新数据，不拷贝，不改变指针（指针不变） |

</details>

**11.** 以下代码中 `%p` 打印的地址前后会一样吗？为什么？

```go
slice := make([]int, 4)
fmt.Printf("%p\n", slice)
slice = append(slice, 1, 2, 3)
fmt.Printf("%p\n", slice)
```

<details><summary>答案</summary>

**不一样。** 初始 cap=4，append 3 个元素后 len=7 超过了 cap，触发扩容，底层创建了新数组，指针改变。

注意：`fmt.Printf("%p", slice)` 不需要加 `&`，Go 对 `%p` + slice 有特殊处理，直接打印 slice 内部指向底层数组的指针。

这里直接输出slice，输出的是其指向的内容的地址

但是 &slice 输出的才是其自身地址
</details>

## 五、copy 函数

**12.** `copy(dst, src)` 的"最短长度"原理是什么？以下代码输出什么？

```go
a := []int{1, 2, 3, 4, 5}
b := make([]int, 2)
copy(b, a)
fmt.Println(b)
```

<details><summary>答案</summary>

**最短长度原理**：`copy` 只复制 `min(len(dst), len(src))` 个元素。

然后剩余的位置如果源目标还有长度则剩余位置元素不变 

输出：`[1 2]`

源有 5 个元素，目标只有 2 个，取最小值 2，只复制了前两个。

</details>

---

**13.** copy 是"破坏性"的吗？以下代码输出什么？

```go
a := []int{1, 2, 3, 4, 5}
slice := make([]int, 1)
slice[0] = 520
copy(slice, a)
fmt.Println(slice)
```

<details><summary>答案</summary>

**是破坏性的**，copy 会直接覆盖目标切片的数据。

输出：`[1]`

目标切片的 520 被源切片的第一个元素 1 覆盖了。

</details>

---

**14.** `copy(a, slice)` 中把 slice 拷贝到 a，如果 a 比较长，a 剩余的元素会怎样？

<details><summary>答案</summary>

**保持不变。** copy 只覆盖前 `min(len(a), len(slice))` 个位置，后面多出来的元素不受影响。

```go
a := []int{1, 2, 3, 4, 5}
slice := []int{9, 9}
copy(a, slice)
fmt.Println(a) // [9, 9, 3, 4, 5] — 后三个不变
```

</details>

## 六、string 与切片

**15.** string 底层是什么？可以对 string 做切片操作吗？

<details><summary>答案</summary>

**string 底层是 byte 数组**，可以做切片操作：

```go
str := "hello@cjj"
slice := str[5:]  // "@cjj"
```

但 string 本身是不可变的，不能直接修改 `str[0] = 'a'`（会报错）。

</details>

---

**16.** 如何修改字符串中的某个字符？如果字符串包含中文，应该用什么类型？

<details><summary>答案</summary>

```go
// 纯英文/ASCII：用 []byte
str := "hello"
arr := []byte(str)
arr[0] = 'a'
str = string(arr)

// 包含中文：必须用 []rune
str := "你好世界"
arr := []rune(str)
arr[0] = '我'
str = string(arr)  // "我好世界"
```

**原因**：中文一个字符占 3 字节，`byte` 只能存 1 字节，会截断。`rune`（int32）按字符处理，兼容所有 Unicode 字符。

</details>

## 七、综合练习

**17.** 编写一个函数 `fbn(n int)`，接收一个 n，返回包含前 n 个斐波那契数的切片 `[]int64`。

<details><summary>答案</summary>

```go
func fbn(n int) []int64 {
    slice := make([]int64, n)
    slice[0] = 1
    slice[1] = 1
    for i := 2; i < n; i++ {
        slice[i] = slice[i-1] + slice[i-2]
    }
    return slice
}
```

注意：`slice[0]` 和 `slice[1]` 需要先初始化，循环从索引 2 开始。

</details>

---

**18.** 切片初始化时，`var slice []int` 声明的切片可以直接用 `slice[0] = 1` 赋值吗？为什么？

<details><summary>答案</summary>

**不可以。** 这样声明的切片是 nil slice，指向 `0x0`（空地址），没有底层数组，直接赋值会 panic。

必须先分配空间，三种方式：
- 引用数组：`slice = arr[:]`
- make：`slice = make([]int, 3)`
- append：`slice = append(slice, 1)`（append 会自动创建空间）

</details>

---

**19.** 切片可以继续切片吗？`sliceInSlice := slice[1:4]` 后修改 `sliceInSlice`，会影响原 `slice` 吗？

<details><summary>答案</summary>

**可以继续切片，且会相互影响。** 切片再切片仍然是共享同一底层数组的引用，修改任一层都会影响其他层。

```go
slice := []int{1, 2, 3, 4, 5}
sub := slice[1:4]  // [2, 3, 4]
sub[1] = 100
fmt.Println(slice)  // [1, 2, 100, 4, 5] — 原切片也被修改了
```

</details>

**20.** 以下哪些初始化方式中，切片的 cap 等于 len？

```go
A. var s = []int{1, 2, 3}
B. var s = make([]int, 4)
C. var s = make([]int, 4, 10)
D. var s = arr[1:3]  // arr 是 [5]int
```

<details><summary>答案</summary>

**A 和 B** 的 cap == len。

- A：直接指定元素，cap = len = 3
- B：make 不指定 cap，cap 默认等于 len = 4
- C：cap=10, len=4，不相等
- D：cap = 5-1 = 4, len = 2，不相等

</details>
