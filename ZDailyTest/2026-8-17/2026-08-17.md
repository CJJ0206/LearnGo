## 一、 Git 底层与排错实战

**1.** `git fetch` 和 `git pull` 在底层逻辑上有什么核心区别？

<details>
<summary>答案</summary>

* `git fetch`：只去远程服务器"巡视"一圈，把最新的提交记录下载到本地隐藏缓存中，**绝对不会**修改你本地的代码和工作区。
* `git pull`：等于 `git fetch` + `git merge`。不仅下载更新，还会直接把远程的新代码融合（覆盖/合并）到你当前的本地文件中。

</details>

---

**2.** 终端执行 `git pull` 报错提示 `config.yaml` 会被覆盖，但执行 `git status` 却显示工作区干净 (`working tree clean`)。这是什么原因？如何通过物理手段彻底破局？

<details>
<summary>答案</summary>

**原因**：文件可能被编辑器或后台进程锁死（占用），或者文件被打了 Git 忽略标记但实际有修改，导致 Git 缓存和系统状态撕裂。
**物理解决手段**：

1. 关闭占用该文件的编辑器或后台服务。
2. 直接在文件管理器中**物理删除**该文件。
3. 执行 `git reset --hard origin/目标分支`，强行用远程的全新文件覆盖本地。

</details>

---

**3.** 如果你在本地修改了配置，但想暂时不提交，先拉取远程新代码。应该配合 `git stash` 执行哪三步？如果暂存区的数据最后不需要了，用什么命令丢弃？

<details>
<summary>答案</summary>

**拉取三步曲**：

1. `git stash` （把本地修改藏起来）
2. `git pull origin 某分支` （安全拉取新代码）
3. `git stash pop` （把藏起来的修改重新拿出来）

**丢弃废弃暂存**：使用 `git stash drop`。

</details>

---

**4.** 你在自己的 `dev-cjj` 分支上开发，想要把别人刚推到 `dev` 分支的最新代码同步到你当前的分支里，标准的命令是哪两句？

<details>
<summary>答案</summary>

不能直接 `git pull`，标准操作是：

1. `git fetch origin` （抓取所有人最新的远程动态）
2. `git merge origin/dev` （把远程的 dev 分支融合进你当前的 dev-cjj 分支）

</details>

## 二、 Slices 高级操作 (SortFunc & CompactFunc)

**5.** 在 `slices.SortFunc(arr, cmp)` 中，你的自定义函数返回 `-1`、`0`、`1`，底层的 pdqsort 引擎分别会怎么做？

<details>
<summary>答案</summary>

假设对比的是 `a` 和 `b`：

* **返回 `< 0`（如 -1）**：判定 `a` 比较小，将 `a` 放在 `b` 的**前面**。
* **返回 `> 0`（如 1）**：判定 `a` 比较大，将 `a` 放在 `b` 的**后面**。
* **返回 `0`**：判定两者权重**相等**，触发优化机制，跳过无意义的位置交换。

</details>

---

**6.** 为什么引入 `cmp.Compare` 返回 `0` 的机制，能大幅优化包含大量重复元素的切片排序性能？

<details>
<summary>答案</summary>

在传统的快速排序中，如果全是重复元素，时间复杂度会退化到 O(N²)。有了返回 `0` 的能力，底层算法一旦收到 `0`，就知道这两个元素相等，会直接将它们跳过或聚拢在中间，避免了大量不必要的比较和内存交换，将复杂度降至逼近 O(N)。

</details>

---

**7.** 默认 `cmp.Compare(a.Age, b.Age)` 是升序排列。在不添加 `if-else` 的情况下，写出两种实现降序的修改方式。

<details>
<summary>答案</summary>

* **方式一（对调参数，推荐）**：`cmp.Compare(b.Age, a.Age)`，利用前大后小返回正数的底层机制欺骗排序器。
* **方式二（结果取反）**：`-cmp.Compare(a.Age, b.Age)`，强制将升序的判定结果颠倒。

</details>

---

**8.** 为什么直接对一个无序且包含重复数据的切片调用 `slices.CompactFunc` 无法完成去重？正确的"组合拳"是什么？

<details>
<summary>答案</summary>

**原因**：`CompactFunc` 是一个"相邻去重器"，它底层只对比紧挨着的两个元素。如果相同的元素没有挨在一起，它会全部判断为不重复。
**正确组合拳**：必须**先 Sort（将相同元素聚拢），**再 Compact**（压缩相邻重复项）。

</details>

---

**9.** 调用 `s = slices.CompactFunc(s, eq)` 后，原切片的 `len` 和 `cap` 会发生什么变化？

<details>
<summary>答案</summary>

* `len`（长度）：**变小**。变为压缩后不重复元素的实际数量。
* `cap`（容量）：**不变**。因为压缩操作是在原底层数组上"原地（In-place）"覆盖完成的，没有开辟新内存。

</details>

---

**10.** 在 Go 1.21 以后，`CompactFunc` 压缩完数据后，底层为了防止内存泄漏，对尾部多出来的废弃空间做了一个什么隐藏操作？

<details>
<summary>答案</summary>

底层会自动将移动后空出来的尾部位置的元素**清零（赋为零值，如 nil）**。这切断了对废弃对象的内存引用，使 Go 的垃圾回收器 (GC) 能够顺利清理它们。

</details>

## 三、 面向对象：抽象与封装

**11.** 什么是面向对象中的"抽象"？Go 语言是如何体现它的？

<details>
<summary>答案</summary>

抽象是指把一类事物的共有属性（字段）和行为（方法）提取出来，形成一个物理模板。Go 语言中主要通过定义结构体（`struct`）来实现这种抽象。

</details>

---

**12.** 结构体及其字段首字母小写后，如何让其他包能够合法地实例化并修改数据？（写出封装的三步操作）

<details>
<summary>答案</summary>

1. 提供一个首字母大写的**工厂模式函数**（如 `NewStudent`）作为暴露接口来返回实例。
2. 提供一个首字母大写的 `Set` 方法用于数据验证和赋值。
3. 提供一个首字母大写的 `Get` 方法用于获取属性值。

</details>

---

**13.** 在编写 Get 方法时，如果图省事直接返回了私有属性的指针（如 `func (s *student) GetScore() *float64`），会引发什么严重后果？应该如何修复？

<details>
<summary>答案</summary>

**后果**：外部包拿到指针后可以解引用（如 `*score = 99.1`），直接篡改底层私有数据，彻底破坏封装性。
**修复**：直接返回值类型（如 `float64`）。此时发生的是值拷贝，外部拿到的是副本，不影响内部真实值。

</details>

## 四、 面向对象：继承、组合与多态陷阱

**14.** Go 语言中如何实现面向对象的"继承"？

<details>
<summary>答案</summary>

通过在结构体内部嵌套**共有匿名结构体**来实现。外层结构体可以直接复用并访问嵌套匿名结构体所有的字段和方法（不论大小写）。

</details>

---

**15.** 结构体中也可以嵌套匿名的基本数据类型，比如：

```go
type B struct {
	A
	float64
}

```

此时外层结构体该如何访问和打印这个 `float64` 的值？

<details>
<summary>答案</summary>

可以直接通过**数据类型本身的名字**来访问，例如：`b.float64 = 3.14`，`fmt.Println(b.float64)`。

</details>

---

**16.** 【就近原则陷阱】假设结构体 B 嵌套了匿名结构体 A，且两者都有一个 `Name` 字段。直接执行 `b.Name = "cjj"`，修改的是哪一个 `Name`？为什么？

<details>
<summary>答案</summary>

修改的是外层结构体 **B** 自己的 `Name`。
因为编译器采用**就近原则**：首先看结构体本身有没有对应的字段，如果有就直接用，没有才会去匿名结构体里找。

</details>

---

**17.** 接上题，如果想明确给内部匿名结构体 A 的 `Name` 赋值，正确的代码格式是什么？

<details>
<summary>答案</summary>

必须明确指定匿名结构体的名字来消除歧义：`b.A.Name = "cjj"`。

</details>

---

**18.** 如果一个方法绑定在结构体 `A` 上（`func (a *A) hello() { fmt.Println(a.Name) }`），你用 `b.Name = "jack"` 赋了值，然后执行 `b.hello()`，控制台会输出 jack 吗？为什么？

<details>
<summary>答案</summary>

**不会**（输出空串）。
因为方法是绑定在内部匿名结构体 `A` 上的，它执行时内部找的也是 `A` 的 `Name`。而你刚才利用就近原则只赋给了外层 `B` 的 `Name`，内部 `A` 的 `Name` 依然为空。

</details>

---

**19.** 【多重继承冲突】如果结构体 C 嵌套了 `AA` 和 `BB` 两个匿名结构体，而这两个匿名结构体里碰巧都有一个名为 `age` 的字段。直接使用 `c.age` 会发生什么？

<details>
<summary>答案</summary>

**编译器会报错**。当多重继承含有相同属性字段时，编译器不知道该采用哪一个，所以必须明确指定具体的匿名结构体名（如 `c.AA.age` 或 `c.BB.age`）。

</details>

---

**20.** 面向对象的"继承"在 Go 里是用**匿名嵌套**模拟的，而"组合"是用**有名嵌套**模拟的（如 `type D struct { a AA }`）。它们两者在语法调用层级上有什么最严厉的区别？

<details>
<summary>答案</summary>

* **继承（匿名嵌套）**：可以省略匿名结构体的名字，直接跨层级访问属性（例如 `b.A.Name` 可以简写为 `b.Name`）。
* **组合（有名嵌套）**：有极强的层级壁垒，在访问字段或方法时，**必须**带上有名结构体的名字（例如只能写 `d.a.Name`，严禁写成 `d.Name` 或 `d.AA.Name`）。

</details>
