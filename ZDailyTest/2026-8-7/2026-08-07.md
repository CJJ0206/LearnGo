## 一、错误处理

**1.** Go 处理异常的三种机制是什么？分别用在什么场景？

<details><summary>答案</summary>

| 机制 | 场景 |
|------|------|
| `defer` | 延迟执行，用于资源清理（关闭文件、解锁） |
| `panic` | 程序遇到无法恢复的严重错误时主动抛出 |
| `recover` | 在 defer 中捕获 panic，使程序不至于崩溃 |

三者配合使用的典型模式：
```go
defer func() {
    if err := recover(); err != nil {
        fmt.Println("捕获到异常:", err)
    }
}()
```

</details>

---

**2.** `recover()` 必须放在哪里使用？直接放在普通函数中有效吗？

<details><summary>答案</summary>

`recover()` **必须放在 defer 调用的函数中**才有效。直接放在普通函数中无效，返回 `nil`。

```go
// ✅ 正确
defer func() {
    if err := recover(); err != nil { ... }
}()

// ❌ 错误 — recover 返回 nil，无法捕获 panic
func test() {
    err := recover()  // 无效
}
```

</details>

---

**3.** 以下代码输出什么？`fmt.Println("继续执行")` 会被执行吗？

```go
func test() {
    defer func() {
        if err := recover(); err != nil {
            fmt.Println("err =", err)
        }
    }()
    num1 := 2
    num2 := 0
    res := num1 / num2
    fmt.Println(res)
}
test()
fmt.Println("继续执行")
```

<details><summary>答案</summary>

```
err = runtime error: integer divide by zero
继续执行
```

`num1 / num2` 触发 panic（除以零），defer 中的 recover 捕获异常，打印错误信息后程序正常继续。所以 `"继续执行"` **会被执行**。

如果没有 recover，程序会直接崩溃，后面的代码都不会执行。

</details>

---

**4.** `errors.New("读取文件错误")` 返回的是什么类型？和 `fmt.Errorf()` 有什么区别？

<details><summary>答案</summary>

返回 `error` 接口类型。

```go
err1 := errors.New("读取文件错误")            // 简单错误消息
err2 := fmt.Errorf("读取 %s 失败", filename)  // 支持格式化
```

`fmt.Errorf` 可以格式化错误消息，`errors.New` 只能传纯字符串。`fmt.Errorf` 还可以用 `%w` 包装已有错误（Go 1.13+）。

</details>

---

**5.** `panic` 和 `fmt.Println(err)` 有什么区别？什么时候用 panic？

<details><summary>答案</summary>

- `fmt.Println(err)`：只是打印错误信息，程序继续执行
- `panic(err)`：立即终止程序，触发 defer 链，输出堆栈信息后崩溃

**panic 使用场景**：遇到不可恢复的严重错误（如配置文件缺失、数据库连不上），继续执行可能造成数据损坏时。**一般情况下优先返回 error，让调用者决定如何处理。**

</details>

## 二、猜数字综合练习

**6.** 以下代码中 `rand.IntN(100) + 1` 生成的随机数范围是多少？`rand.IntN(100)` 的范围呢？

<details><summary>答案</summary>

- `rand.IntN(100)` → `[0, 100)`，即 0~99
- `rand.IntN(100) + 1` → `[1, 100]`，即 1~100

</details>

**7.** 猜数字程序中，当用户输入非数字内容时，`fmt.Scanln` 会怎样？如何优雅处理？

<details><summary>答案</summary>

`fmt.Scanln` 返回 `(n, error)`。输入非数字时，error 不为 nil，且输入缓冲区会残留非法字符。

处理方式：
```go
_, err := fmt.Scanln(&guessNum)
if err != nil {
    fmt.Println("输入错误，请输入数字")
    continue  // 跳过本次循环，让用户重新输入
}
```

</details>

## 三、三天打鱼两天晒网

**8.** 已知 1990.1.1 开始"三天打鱼两天晒网"，如何判断 2026-08-07 该打鱼还是晒网？写出核心逻辑。

<details><summary>答案</summary>

```go
startDate, _ := time.Parse("2006-01-02", "1990-01-01")
targetDate, _ := time.Parse("2006-01-02", "2026-08-07")
diff := targetDate.Sub(startDate)
totalDays := int(diff.Hours() / 24)

// 5天一个周期：前3天打鱼，后2天晒网
remainder := totalDays % 5
if remainder == 0 || remainder == 4 {
    fmt.Println("晒网")  // 第4、5天（余数0或4）
} else {
    fmt.Println("打鱼")  // 第1、2、3天（余数1、2、3）
}
```

注意：1990.1.1 是第 1 天（打鱼），余数 1,2,3 → 打鱼，余数 4,0 → 晒网。

</details>

## 四、数组定义与内存布局

**9.** 数组的内存布局有什么特点？`&arr[0]` 和 `&arr` 有什么关系？

<details><summary>答案</summary>

**数组的内存是连续的。** 数组的地址就是首元素的地址：

```go
var arr [3]int
fmt.Printf("%p\n", &arr)     // 输出数组地址
fmt.Println(&arr[0])          // 地址相同！
fmt.Println(&arr[1])          // 地址 = 首元素地址 + 8（int 占8字节）
```

连续内存布局意味着：通过地址偏移就能快速访问任意元素，不需要遍历。

</details>

**10.** 写出数组的四种初始化方式。

<details><summary>答案</summary>

```go
// 方式一：声明 + 完整赋值
var a1 [3]int = [3]int{1, 2, 3}

// 方式二：类型推导
var a2 = [3]int{1, 2, 3}

// 方式三：... 让编译器推导长度
var a3 = [...]int{1, 2, 3, 4, 5}

// 方式四：指定索引赋值
var a4 = [3]string{1: "tom", 2: "jerry", 0: "cjj"}
```

</details>

**11.** Go 中数组是值类型还是引用类型？传递数组给函数时会发生什么？

<details><summary>答案</summary>

**数组是值类型。** 将数组传给函数时，会**拷贝整个数组**。修改函数内的数组不会影响原数组。

```go
func modify(arr [3]int) {
    arr[0] = 999  // 只修改副本
}

a := [3]int{1, 2, 3}
modify(a)
fmt.Println(a)  // [1, 2, 3] — 未受影响
```

如果数组很大，拷贝开销也很大。这时可以传指针 `*[3]int` 或改用切片。

</details>

## 五、切片入门

**12.** 切片和数组在定义语法上最直观的区别是什么？

<details><summary>答案</summary>

数组中括号内必须指定长度，切片不指定：

```go
var arr [5]int   // 数组：长度固定
var s []int      // 切片：长度可变
```

</details>

---

**13.** 以下代码输出什么？`cap(slice)` 的值是多少？

```go
var intArr = [5]int{1, 2, 3, 4, 5}
slice := intArr[1:3]
fmt.Println(slice)
fmt.Println(len(slice))
fmt.Println(cap(slice))
```

<details><summary>答案</summary>

```
[2 3]
2
4
```

- `slice`：`[1:3]` 左闭右开，包含索引 1、2 的元素 → `[2, 3]`
- `len(slice)`：元素个数 = 2
- `cap(slice)`：从切片起始位置到数组末尾的容量 = 4（索引 1,2,3,4 共 4 个位置）

切片容量 = 底层数组长度 - 切片起始索引。

</details>

---

**14.** 切片是值类型还是引用类型？修改切片元素会影响底层数组吗？

<details><summary>答案</summary>

**切片是引用类型。** 切片不存储数据，只是对底层数组的"视图"（包含指针、长度、容量）。

修改切片元素**会直接影响底层数组**：

```go
arr := [5]int{1, 2, 3, 4, 5}
s := arr[1:3]
s[0] = 999
fmt.Println(arr)  // [1, 999, 3, 4, 5] — 底层数组被修改了
```

</details>

---

**15.** 切片为什么通常比数组更常用？

<details><summary>答案</summary>

1. **长度可变**：可以动态增长，数组长度固定
2. **引用传递效率高**：传切片只拷贝 24 字节的 slice header，而数组要拷贝全部数据
3. **灵活**：可以共享底层数组，创建多个视图
4. **Go 标准库广泛使用**：几乎所有集合操作都用切片

</details>
