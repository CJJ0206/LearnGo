## 一、接口基本概念

**1.** Go 中 `interface` 是什么？接口里的方法有什么特点？接口能包含成员变量吗？

<details><summary>答案</summary>

接口定义了一组**方法签名（不需要实现）**，到某个自定义类型要使用的时候，再根据具体情况把这些方法写出来。

- 接口里的所有方法都**没有方法体**（即没有具体实现内容）
- 接口**不能包含任何变量**
- 只要一个自定义类型含有接口类型中的**所有方法**，这个变量就实现了这个接口（Go 不需要显式声明）

```go
type Usb interface {
    Start()
    Stop()
}
```

</details>

---

**2.** 什么是"非侵入式设计（隐式实现）"？对比 Java/C++ 的 `implements` 有何区别？

<details><summary>答案</summary>

- **传统 OO 语言（Java/C++）**：实现类必须显式声明 `implements SomeInterface`，这意味着实现类必须知道并依赖接口的存在，若接口在第三方包则必须引入那个包。
- **Go（非侵入式）**：只要一个类型实现了接口要求的**全部方法**，它就**自动**实现了该接口，**不需要任何关键字声明**。实现类完全不需要知道接口的存在，接口修改也不会强制实现类改代码（只要方法签名不变），从而实现实现方与接口定义方的彻底解耦。

</details>

---

**3.** 判断：`type Phone struct{}` 只要实现了 `Start()` 和 `Stop()` 两个方法，就自动实现了包含这两个方法的 `Usb` 接口，且不需要任何关键字声明。对还是错？

<details><summary>答案</summary>

**正确（对）。** 这正是 Go 隐式实现的典型特征——方法签名匹配即视为实现，无需 `implements` 之类的关键字。

```go
type Usb interface { Start(); Stop() }
type Phone struct{}
func (p *Phone) Start() { fmt.Println("手机开始工作") }
func (p *Phone) Stop()  { fmt.Println("手机停止工作") }
// *Phone 自动实现了 Usb 接口
```

</details>

---

**4.** Go 接口的"低耦合"主要体现在哪两点？

<details><summary>答案</summary>

1. **非侵入式设计（隐式实现）**：实现方不依赖接口定义方，见第 2 题。
2. **接口由"使用者"定义，而非"提供者"**：Go 最佳实践把接口定义在使用它的包里。例如写日志函数时，可在自己包里定义含 `Write()` 的接口，直接接收标准库的 `os.File`；标准库作者写 `os.File` 时根本不知道你会怎么用。这就是**依赖倒置（DIP）**。

</details>

---

**5.** Go 接口的"高内聚"体现在哪？举出标准库中最经典的小接口例子，以及组合的例子。

<details><summary>答案</summary>

- **小接口（接口隔离原则极致）**：Go 推崇只含 1~2 个方法的"小接口"，内聚性最高。最经典的是 `io.Reader`（仅 `Read`）和 `io.Writer`（仅 `Write`）——一个方法只描述一种明确单一的行为。
- **通过组合构建复杂行为**：Go 不鼓励几十个方法的大接口，而是用接口嵌套组合表达复杂行为。例如 `io.ReadWriter` 就是组合 `io.Reader` 和 `io.Writer` 得到的，"积木式"设计保证底层抽象高内聚，上层按需组合。

</details>

## 二、接口实现与多态（USB 示例）

**6.** 在 `interface/main.go` 中，`Computer.Work(usb Usb2)` 能同时接收 `*Phone` 和 `*Camera`，这演示了接口的什么特性？为什么调用时不需要任何额外声明？

<details><summary>答案</summary>

演示了**多态**：`Computer.Work` 只认 `Usb2` 接口，至于传进来的具体是谁（手机/相机），只要实现了 `Start`/`Stop` 即可，运行时自动识别对接。

不需要额外声明，正是得益于 Go 接口的**低耦合（隐式实现）**——调用方只依赖接口方法签名，不关心具体类型，也不需要在调用处做任何类型声明或注册。

```go
c := Computer{}
c.Work(&Phone{})   // 手机开始工作 / 手机停止工作
c.Work(&Camera{})  // 相机开始工作 / 相机停止工作
```

</details>

---

**7.** 一个接口 `Usb` 和 `Usb2` 方法签名完全一致，`Phone` 同时实现了两者。这在 Java 等语言中做得到吗？为什么？

<details><summary>答案</summary>

**在 Go 里可以，且很自然；在传统语言中通常做不到"一个类同时被两个不同接口名认可"而不改代码。** Go 的隐式实现意味着：只要 `Phone` 有 `Start`/`Stop`，它就同时是 `Usb` 和 `Usb2` 的实现者，无需写两份声明。这正是传统 `implements` 显式绑定做不到的灵活性。

</details>

## 三、接口注意事项（Details.md）

**8.** 接口本身能直接创建实例吗？能不能让接口变量指向一个实现了该接口的自定义类型实例？

<details><summary>答案</summary>

- 接口本身**不能创建实例**。
- 但是接口变量**可以指向**一个实现了该接口的自定义类型的变量（实例）：

```go
type Usb interface{ Say() }
type Student struct{ name string }
func (stu *Student) Say() { fmt.Println("Say") }
var usb Usb = &Student{}  // 指向实现了接口的实例，OK
usb.Say()
```

</details>

---

**9.** 一个自定义类型要"实现"某接口，必须满足什么条件？

<details><summary>答案</summary>

必须**把该接口声明的所有方法都实现**（方法名、参数、返回值全部匹配）。只实现部分方法不算实现该接口，也就不能把该类型实例赋给接口变量。

</details>

---

**10.** 只有结构体（struct）才能实现接口吗？用 `type integer int` 实现 `Say()/Leave()` 接口的例子说明。

<details><summary>答案</summary>

**不是，只要能绑定方法的自定义数据类型都可以**，包括基于内建类型定义的类型（如 `integer`）：

```go
type a interface { Say(); Leave() }
type integer int
func (i integer) Say()   { fmt.Println("here is integer") }
func (i integer) Leave() { fmt.Println("here is integer") }

var i integer = 10
var b a = i   // 把实现了接口的变量赋值给接口，成功
b.Say()
```

</details>

---

**11.** 一个自定义类型能同时实现多个接口吗？举例说明。

<details><summary>答案</summary>

**能。** 例如 `monster` 同时实现 `A`（`Say`）和 `B`（`Hello`）两个接口，之后可用各自的接口变量分别调用，非常灵活：

```go
type A interface { Say() }
type B interface { Hello() }
type monster struct{}
func (m *monster) Say()   { fmt.Println("say") }
func (m *monster) Hello() { fmt.Println("hello") }

var mon monster
var a A = &mon
var b B = &mon
a.Say(); b.Hello()
```

</details>

---

**12.** 接口可以继承其它接口吗？若 `Cinterface` 内嵌 `Ainterface` 和 `Binterface`，要实现 C 还要实现哪些方法？

<details><summary>答案</summary>

**可以。** 接口能通过内嵌继承别的接口。若要"实现"子接口 `C`，必须**把 C 自身声明的 + 它继承的所有父接口的方法全部实现**，缺一不可。

```go
type A interface { test01() }
type B interface { test02() }
type C interface { A; B; test03() }
// 实现 C 必须同时实现 test01、test02、test03
```

</details>

**13.** 下面代码为什么报错？如何修正？

```go
type Ainterface interface { test1() }
type Binterface interface { test1() }
type Cinterface interface {
    Ainterface
    Binterface
}
```

<details><summary>答案</summary>

**报错原因**：`Cinterface` 同时内嵌了 `Ainterface` 和 `Binterface`，二者都有同名方法 `test1()`，导致 `Cinterface` 内部出现两个完全一样的 `test1()`，产生歧义/冲突，编译报错。

**修正方式**（任选其一）：
- 去掉其中一方的继承，只保留一个 `test1()` 来源；
- 或把其中一个父接口的方法改名（如 `Binterface` 改成 `test3()`），消除同名冲突；
- 或干脆不内嵌、直接在 `Cinterface` 中只声明一次 `test1()`。

</details>

---

**14.** `interface` 类型默认是什么种类（值/引用）？未初始化就使用返回什么？

<details><summary>答案</summary>

接口在 Go 中**默认是引用类型（内部含指针）**。如果没有对接口初始化就使用，接口变量的值为 **`nil`**。

</details>

---

**15.** 空接口 `interface{}` 有什么特殊性？它能被什么类型赋值？

<details><summary>答案</summary>

空接口**没有任何方法**，因此**所有类型都自动实现了空接口**。它可以接收任意类型的值（常作为"任意类型"容器或函数参数），例如：

```go
var x interface{} = 10
x = "hello"
x = struct{}{}
```

</details>

## 四、接口应用——排序（useAndDetails / testsort）

**16.** `sort.Sort(data Interface)` 要求数据结构实现哪三个方法？各自作用是什么？

<details><summary>答案</summary>

`sort.Sort` 接收实现了 `sort.Interface` 的数据，该接口要求三个方法：

| 方法 | 作用 |
|------|------|
| `Len() int` | 返回数据长度（集合有多少个元素） |
| `Less(i, j int) bool` | 定义排序规则：当索引 i 的元素"应排在前"时返回 true |
| `Swap(i, j int)` | 交换 i、j 两个位置的元素 |

排序算法本身只通过这三个"问句"驱动，不关心底层是 int 切片还是复杂结构体——算法与数据结构彻底分离。

</details>

---

**17.** 在 `HeroSlice` 的 `Less` 中写 `h[i].age > h[j].age` 表示升序还是降序？如果要改成按年龄升序该怎么写？

<details><summary>答案</summary>

`h[i].age > h[j].age` 表示**降序**（年龄大的排前面）。

因为 `Less` 返回 true 意味着 i 应排在 j 前面；当 i 的年龄更大时返回 true，即大龄在前 → 降序。

改成**升序**：`return h[i].age < h[j].age`

```go
func (h HeroSlice) Less(i, j int) bool {
    return h[i].age < h[j].age  // 升序
}
```

</details>

---

**18.** `var stuSlice []Student` 与 `type stuSlice []Student` 有什么区别？为什么前者不能直接作为类型传给 `sort.Sort`？

<details><summary>答案</summary>

- `var stuSlice []Student`：这是**声明一个变量**，不是类型，所以**不能**写在函数参数列表里当类型用。
- `type stuSlice []Student`：这是**定义一个命名类型**，可以在其上面绑定方法（如 `Len/Less/Swap`），从而满足接口，也才能作为类型传参。

```go
type stuSlice []Student           // 这样才是对的，可以绑定方法
func (stu stuSlice) Len() int { return len(stu) }
```

</details>

**19.** `Swap` 里 `stu[i], stu[j] = stu[j], stu[i]` 与用临时变量交换等价吗？为什么 Go 的多重赋值能保证交换安全？

<details><summary>答案</summary>

**等价且安全。** Go 在处理多重赋值时，会**先完整计算出等号右边所有值**，然后统一赋值给左边的变量。即先取出 `stu[j]`、`stu[i]` 暂存，再同时写入，因此无需临时变量也不会覆盖丢失：

```go
// 与下面的写法完全等价
stu[i], stu[j] = stu[j], stu[i]
// temp := stu[i]; stu[i] = stu[j]; stu[j] = temp
```

</details>

**20.** `useAndDetails/main.go` 中提到现在官方更推荐哪种排序方式？相比 `sort.Sort` 它有什么优势？

<details><summary>答案</summary>

更推荐 **`slices.SortFunc`**（配合 `cmp.Compare`）。

优势：**不需要手写 `Len/Less/Swap` 三个方法、不用为切片单独定义命名类型**，只需传一个比较函数即可，代码量更少、更直接：

```go
slices.SortFunc(devs, func(a, b device) int {
    if a.temperature != b.temperature {
        return cmp.Compare(a.temperature, b.temperature)
    }
    return cmp.Compare(a.id, b.id)
})
```

（注：`sort.Sort` 仍可用，适合需要复用排序逻辑/自定义类型的旧式写法。）

</details>

**21.** `testsort/main.go` 中 `deviceSlice` 的 `Less` 实现了几级排序？为什么先比 `id` 再比 `temperature`？`slices.SortFunc` 版本里若"写反了"会怎样？

<details><summary>答案</summary>

`deviceSlice.Less` 实现了**两级排序**：第一优先级 `id`，相等时再比 `temperature`。这样保证排序稳定可预期——同 id 的设备按温度排，不同 id 的先按 id 排。

`testsort` 里的 `slices.SortFunc` 版本把**优先级写反了**（先比 `temperature`、再比 `id`），与上面 `deviceSlice` 的"id 优先"相反，因此二者最终顺序不同。若比较函数在 `Less` 里把 `<`/`>` 写反，则整体顺序会反转（升序变降序）。

</details>

## 五、继承 + 接口结合（inheritAndInterface）

**22.** `type LittleMonkey struct { Monkey }` 这种写法在 Go 中实现了什么？叫什么形式的继承？

<details><summary>答案</summary>

这是 Go 通过**结构体匿名嵌套（嵌入）**实现的"继承"（组合式继承 / 匿名结构体继承）。`LittleMonkey` 嵌入了 `Monkey`，从而可以直接复用 `Monkey` 的字段与方法：

```go
type Monkey struct { name string }
type LittleMonkey struct { Monkey }  // 匿名嵌入，相当于继承
m := &LittleMonkey{Monkey{name: "悟空"}}
fmt.Println(m.name)  // 直接访问父结构体字段
```

</details>

---

**23.** 接口可以看作是对继承的什么？为何"足球运动员"和"大学生"学英语要用接口而非各自绑定方法？

<details><summary>答案</summary>

接口可以看作是对继承的**补充**。

如果直接给 `footballPlayer` 和 `collegeStudent` 各自单独绑定 `learn()` 方法，会出现"一个人一个写法"的问题，**不规范、难统一约束**。改用接口 `learnEnglish` 定义规范，要求相关类型都去实现 `learn()`，则行为被统一约束、调用方式一致，便于管理和扩展。

</details>

---

**24.** 继承的价值 与 接口的价值 分别是什么？

<details><summary>答案</summary>

- **继承的价值**：提升**代码复用性和可维护性**（父子共享字段与方法）。
- **接口的价值**：在于**设计**——设计好各种规范（方法签名），让其它自定义类型去实现这些方法，实现解耦与多态。

</details>

**25.** `letItFly(f fly)` 与 `Reporter(g GetWeight)` 这类"接收接口类型"的通用函数有什么好处？

<details><summary>答案</summary>

它们是"面向接口编程"的通用函数，好处：

1. **解耦**：函数只依赖接口方法，不关心具体类型。
2. **可扩展**：新增任意实现了该接口的类型，无需改函数代码（开闭原则）。
3. **多态**：同一函数对不同的实现者表现不同行为，例如 `letItFly(m/b/s)` 分别让小猴、鸟、超人"飞"，`Reporter(monkey/bird)` 自动识别并称重。

```go
func letItFly(f fly) { f.flying() }
func Reporter(g GetWeight) { fmt.Printf("动物 %s 重量: %fkg\n", "no", g.getAnimalWeight()) }
```

</details>
