## 一、 基础概念与选择题

### 1. 关于 Go 语言中“方法（Method）”的绑定规则与声明，下列说法正确的是（ ）

A. Go 方法只能与 `struct`（结构体）类型绑定，不能与基础数据类型（如 `int`、`float`）绑定  
B. 方法可以通过结构体名称直接调用，例如 `Person.speak()`，无需实例化对象  
C. 方法是作用在指定数据类型上的，只要是同一包内自定义的数据类型（如 `type Integer int`），都可以绑定方法  
D. 方法的接收者变量名（如 `func (p Person) ...` 中的 `p`）是系统固定关键字，不能自定义修改  

<details>
<summary>答案</summary>

**正确答案：C**

- **A 项错误**：Go 中的方法可以绑定到任何同一包内**自定义的数据类型**上（例如 `type Integer int`），不仅限于 `struct`。
- **B 项错误**：方法必须由绑定类型的实例（变量或指针）来调用，如 `person1.speak()`，不能直接通过类型名调用。
- **C 项正确**：只要是当前包内定义的类型（包括结构体和自定义基础类型），都可以声明绑定方法。
- **D 项错误**：接收者变量名（如 `p`）由程序员自由命名，通常取类型首字母小写。

</details>

### 2. 关于“值接收者” `(p Person)` 与“指针接收者” `(p *Person)` 方法的区别，说法错误的是（ ）

A. 值接收者方法在调用时，会把调用者变量**深拷贝/值拷贝**一份传给方法空间  
B. 指针接收者方法传的是地址，在方法内部修改结构体字段会直接改变外部原变量的值  
C. 当结构体包含大量字段或空间占用较大时，推荐使用值接收者以保证数据安全性  
D. 行业实践中，80% 以上的情况推荐统一使用“指针接收者”  

<details>
<summary>答案</summary>

**正确答案：C**

- **C 项错误**：当结构体非常大时，使用值接收者会在每次方法调用时产生较大的内存拷贝开销，此时应该强烈推荐使用**指针接收者**来提升性能、节省内存。

</details>

### 3. 假设定义了自定义类型 `type Age int`，并为其绑定了方法 `func (a Age) IsAdult() bool`。下列调用方式正确的是（ ）

A. `Age(18).IsAdult()`  
B. `18.IsAdult()`  
C. `var a int = 18; a.IsAdult()`  
D. `IsAdult(18)`  

<details>
<summary>答案</summary>

**正确答案：A**

- **解析**：普通字面量 `18` 或原生类型 `int` 没有绑定 `IsAdult` 方法。必须先转换为自定义类型 `Age(18)` 或声明 `var a Age = 18` 后，才能通过 `a.IsAdult()` 进行方法调用。

</details>

### 4. 【判断题】

在一个结构体下定义多个方法时，行业规范推荐统一选择“值接收者”或“指针接收者”，避免在一个结构体的方法集中混用这两种接收者。（ ）

<details>
<summary>答案</summary>

**正确答案：对（True）**

- **解析**：为了保持代码接口的一致性与可维护性，同一个结构体下的方法集应该统一选择“值接收者”或“指针接收者”。通常除了数据极小且必须只读的场景外，80% 以上的项目均统一使用指针接收者。

## 二、 代码阅读与输出预测题

### 5. 观察以下代码，写出控制台最终输出的内容

```go
type User struct {
    Name string
}

func (u User) ChangeName1() {
    u.Name = "Tom"
}

func (u *User) ChangeName2() {
    u.Name = "Jerry"
}

func main() {
    u := User{Name: "Alice"}
    u.ChangeName1()
    fmt.Println(u.Name)

    u.ChangeName2()
    fmt.Println(u.Name)
}

```

输出内容：

```text
Alice
Jerry

```

* `ChangeName1()` 使用**值接收者**，`u` 在方法内部是原变量的副本，对 `u.Name` 的修改不影响外部原对象，因此第一行输出 `Alice`。
* `ChangeName2()` 使用**指针接收者**，传入的是原对象的地址，直接修改了原变量，因此第二行输出 `Jerry`。

### 6. 观察以下代码，分析语法糖与底层实际运行结果

```go
type Cat struct {
    Color string
}

func (c Cat) SetColorValue(color string) {
    c.Color = color
}

func main() {
    c := Cat{Color: "White"}
    
    // 使用指针调用“值接收者”方法
    (&c).SetColorValue("Black")
    fmt.Println(c.Color)
}

```

输出内容：

```text
White

```

* **解析**：Go 语言语法上支持用指针 `(&c)` 去调用值接收者方法 `SetColorValue`。编译器在底层会自动将其转换为 `(*(&c)).SetColorValue("Black")`。
* 但由于方法签名本身是**值接收者 `(c Cat)**`，方法体接收到的依然是解引用后的**值副本**，因此外部 `c.Color` 依然保持 `White` 不变。

### 7. 观察以下关于 `fmt.Stringer` 接口与 `String()` 方法的代码，预测输出内容

```go
type Student struct {
    Name string
    Age  int
}

func (s *Student) String() string {
    return fmt.Sprintf("Student[Name=%s, Age=%d]", s.Name, s.Age)
}

func main() {
    s := Student{Name: "cjj", Age: 23}
    fmt.Println(s)
    fmt.Println(&s)
}

```

输出内容：

```text
{cjj 23}
Student[Name=cjj, Age=23]

```

* **解析**：`String()` 方法绑定的是**指针接收者 `(s *Student)**`。
* 当传入 `s`（值类型）给 `fmt.Println` 时，没有实现 `String()` 方法，按默认结构体格式打印 `{cjj 23}`。
* 当传入 `&s`（指针类型）给 `fmt.Println` 时，满足了 `*Student` 的 `String()` 方法，`fmt.Println` 会**自动调用**该方法并输出定制格式 `Student[Name=cjj, Age=23]`。

### 8. 观察以下函数与方法的区别代码，哪一行代码在编译时会直接报错？

```go
type Dog struct{ Name string }

func BarkFunc(d Dog) { fmt.Println(d.Name, "bark") }

func (d Dog) BarkMethod() { fmt.Println(d.Name, "bark") }

func main() {
    dPtr := &Dog{Name: "旺财"}
    
    BarkFunc(dPtr)     // 位置 A
    dPtr.BarkMethod()  // 位置 B
}

```

<details>
<summary>答案</summary>

**位置 A 会直接编译报错。**

* **解析**：
* **普通函数 `BarkFunc(d Dog)**` 参数严格匹配：形参为值类型 `Dog`，传入指针类型 `dPtr (*Dog)` 会直接报类型不匹配错误。
* **方法 `dPtr.BarkMethod()**` 具备语法糖特性：用指针变量调用值接收者方法时，Go 编译器会自动做解引用 `(*dPtr).BarkMethod()` 转换，编译顺利通过。

### 9. 【场景改错题】

新手程序员试图编写一个通用数学工具，代码如下：

```go
package main

import "fmt"

type MathUtils struct{}

func (m MathUtils) Add(a, b int) int {
    return a + b
}

func main() {
    res := MathUtils.Add(1, 2)
    fmt.Println(res)
}

```

该代码在 `MathUtils.Add(1, 2)` 处编译报错。请说明报错原因并写出两种正确的调用方式。

<details>
<summary>答案</summary>

**报错原因**：
Go 语言中的方法不能像 C# / Java 的静态方法一样直接通过结构体类型名调用，必须通过该结构体的**实例**来调用。

**正确调用方式**：

```go
// 方式一：实例化后调用
mu := MathUtils{}
res1 := mu.Add(1, 2)

// 方式二：使用匿名字面量实例直接调用
res2 := MathUtils{}.Add(1, 2)

```

### 12. 【性能与设计解析题】

假定有一个业务结构体 `type BigData struct { buffer [1024]int64 }`，占用 8KB 内存。请解释为什么为其定义方法时，必须优先选择 `func (b *BigData) Process()` 而非 `func (b BigData) Process()`？

* **内存与性能考量**：
* 若使用值接收者 `(b BigData)`，每次调用 `Process()` 方法时，Go 运行时都会在栈区完整拷贝一份 8KB 的数据块。在高并发频繁调用的场景下，这会带来显著的 CPU 内存拷贝开销和 GC 压力。
* 使用指针接收者 `(b *BigData)` 时，传递给方法的仅为一个固定大小的指针（64 位系统下占 8 字节），避免了大数据块的拷贝，性能优势极大。

### 13. 关于 `fmt.Println(x)` 打印变量时触发 `String()` 方法的说法，正确的是（ ）

A. 只要结构体定义了 `String()` 方法，无论值接收者还是指针接收者，`fmt.Println(x)` 都会 100% 触发该方法

B. 若 `String()` 绑定的是指针接收者 `(s *Student)`，则 `fmt.Println(s)`（传入值变量）时不会触发定制打印，只有 `fmt.Println(&s)` 才会触发

C. `String()` 方法可以有多个返回值，如 `(string, error)`

D. `fmt.Println` 内部是通过强转为 `int` 来调用 `String()` 的

<details>
<summary>答案</summary>

**正确答案：B**

* **解析**：
* A/B 项：`fmt.Println` 内部使用接口断言判断变量是否实现了 `fmt.Stringer` 接口（签名必须为 `String() string`）。当 `String()` 绑定在指针接收者 `*Student` 上时，只有 `&s`（指针）满足接口类型，值变量 `s` 不满足，因此不会触发。
* C 项：`String()` 方法签名必须严格为 `String() string`，不能有额外的返回值。

### 15. 【问答题】

对比普通函数与结构体方法，在设计 Go 项目（如计算器类、数据库 Client 工具类）时，使用结构体方法（Method）相较于独立函数（Function）有什么架构设计上的优势？

<details>
<summary>答案</summary>

1. **内聚与高封装**：将数据状态（如计算器的参数、数据库的链接句柄/配置）与业务操作（加减乘除、Query/Exec）绑定在一起，形成高内聚的领域模型。
2. **避免全局变量污染**：独立函数往往需要依赖全局变量或在每次调用时传入大量的重复配置参数，而方法可以直接复用结构体字段中的配置状态。
3. **面向接口编程**：绑定了方法的结构体可以隐式实现 Go 的 `interface`，便于后续进行 Mock 测试、依赖注入以及多态扩展。
