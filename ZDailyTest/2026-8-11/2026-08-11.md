## 一、基础概念与选择题

### 1. 关于 Go 语言中结构体（Struct）的内存布局与访问效率，下列说法正确的是（ ）

A. 结构体是引用类型，新建变量时仅在栈区开辟指针大小的空间  
B. 若结构体字段全为值类型（如 int、float），其在内存中是连续扁平分布的，CPU 缓存命中率高  
C. 若结构体字段包含指针类型，指针指向的具体数据也会强制排列在结构体的同一块连续内存中  
D. 嵌套结构体只能通过指针实现，值嵌套会导致编译阶段循环引用错误  

<details>
<summary>答案</summary>

**正确答案：B**

- **A 项错误**：结构体是**值类型**，新建变量时直接开辟包含所有字段的完整连续空间。
- **B 项正确**：无指针的结构体字段在内存中连续排列，访问时可直接通过基地址 + 偏移量快速寻址。
- **C 项错误**：指针字段本身在结构体内存块中连续，但指针指向的数据分散在其他内存地址上。
- **D 项错误**：结构体可以直接进行值类型嵌套。

</details>

### 2. 关于 Go 语言中 `new(T)` 与 `&T{}` 创建结构体的说法，错误的是（ ）

A. `new(T)` 会分配零值内存，并返回指向该内存的指针 `*T`  
B. `&T{}` 同样会分配内存并返回指针 `*T`  
C. `new(T)` 可以在括号内直接指定字段的初始值，例如 `new(Person{"Tom", 18})`  
D. `&T{}` 支持在字面量中对部分或全部字段进行初始化  

<details>
<summary>答案</summary>

**正确答案：C**

- `new` 是 Go 内置的内存分配函数，只能接收类型名称作为参数，例如 `new(Person)`。
- `new(T)` 会将分配的对象初始化为零值，并返回指针 `*T`。
- 不能在 `new()` 中直接传入具体字段值。
- 如果需要创建指针的同时赋值，应使用字面量取地址：

```go
&Person{Name: "Tom", Age: 18}
````

</details>

### 3. 【判断题】

如果结构体 `A` 和 `B` 的字段数量和字段类型完全相同，但字段名称不相同，例如 `A` 包含 `Num int`，`B` 包含 `Value int`，依然可以直接通过 `a = A(b)` 进行强制类型转换。（ ）

<details>
<summary>答案</summary>

**正确答案：错（False）**

Go 对结构体类型转换有严格要求。

需要注意结构体类型是否具有相同的：

1. 字段数量
2. 字段类型
3. 字段顺序
4. 字段 Tag

对于结构体类型之间的显式转换，字段名称本身并不是简单概括为“必须完全相同”的四大条件之一；需要结合 Go 规范中的结构体类型一致性规则判断。

例如：

```go
type A struct {
    Num int
}

type B struct {
    Value int
}
```

这种情况下：

```go
a := A{Num: 10}
b := B(a)
```

可以进行转换。

</details>

### 4. 在结构体字段未显式初始化（处于零值状态）时，对其进行写入操作会导致程序发生 panic 的是（ ）

A. `int` 字段
B. `string` 字段
C. `map` 字段
D. `struct` 值类型嵌套字段

<details>
<summary>答案</summary>

**正确答案：C**

* 结构体中的 `map` 字段零值为 `nil`。
* 在 Go 中，对未通过 `make` 分配的 `nil map` 进行写入，例如：

```go
s.MyMap["key"] = 1
```

会触发运行时错误：

```text
panic: assignment to entry in nil map
```

需要先初始化：

```go
s.MyMap = make(map[string]int)
```

</details>

## 二、代码阅读与输出预测题

### 5. 观察以下代码，预测最终控制台输出的内容

```go
type Student struct {
    Name string
    Age  int
}

func main() {
    s1 := Student{Name: "Alice", Age: 20}
    s2 := s1
    s2.Name = "Bob"

    ps := &s1
    ps.Age = 22

    fmt.Println(s1.Name, s1.Age)
    fmt.Println(s2.Name, s2.Age)
}
```

输出内容：

<details>
<summary>答案</summary>

```text
Alice 22
Bob 20
```

* `s2 := s1` 是结构体的值拷贝。
* `s2.Name = "Bob"` 只修改了 `s2` 的副本，不影响 `s1`。
* `ps := &s1` 获取了 `s1` 的指针。
* 通过指针修改：

```go
ps.Age = 22
```

会直接修改 `s1` 原来的数据，因此 `s1.Age` 变为 `22`。

</details>

### 6. 观察以下包含引用类型字段的结构体代码，写出运行输出

```go
type Player struct {
    Score int
    Items map[string]int
}

func main() {
    p1 := Player{Score: 100, Items: make(map[string]int)}
    p1.Items["gold"] = 50

    p2 := p1
    p2.Score = 200
    p2.Items["gold"] = 99

    fmt.Println(p1.Score, p1.Items["gold"])
}
```

输出内容：

<details>
<summary>答案</summary>

```text
100 99
```

* `Score` 是基本值类型。
* `p2 := p1` 时，`Score` 被复制了一份。
* 因此：

```go
p2.Score = 200
```

不会改变 `p1.Score`，`p1.Score` 仍然是 `100`。

* `Items` 是 `map`。
* 结构体复制时，`map` 本身不会复制底层数据，而是复制其内部引用。
* 因此 `p1.Items` 和 `p2.Items` 指向同一个底层 map。

所以：

```go
p2.Items["gold"] = 99
```

会导致：

```go
p1.Items["gold"] == 99
```

</details>

### 7. 分析以下代码，写出输出结果

```go
type Config struct {
    Host string
    Port int
}

func main() {
    c := &Config{Host: "127.0.0.1", Port: 8080}

    fmt.Println(c)
    fmt.Println(*c)
}
```

输出内容：

<details>
<summary>答案</summary>

```text
&{127.0.0.1 8080}
{127.0.0.1 8080}
```

* `c` 是结构体指针。
* `fmt.Println(c)` 输出指针指向的结构体，并带有 `&` 标志：

```text
&{127.0.0.1 8080}
```

* `*c` 对指针进行了显式解引用：

```go
fmt.Println(*c)
```

因此输出的是结构体值：

```text
{127.0.0.1 8080}
```

</details>

### 8. 观察以下关于类型别名的代码，编译能否通过？如果不能，请说明原因；如果能，写出输出结果

```go
type UserAge int

func main() {
    var a int = 18
    var b UserAge = a
    fmt.Println(b)
}
```

<details>
<summary>答案</summary>

**编译失败，无法通过。**

原因：

```go
type UserAge int
```

定义的是一个新的**命名类型**，而不是类型别名。

虽然：

```go
UserAge
```

的底层类型是：

```go
int
```

但 Go 编译器会将 `int` 和 `UserAge` 视为不同的类型，因此不能直接赋值：

```go
var b UserAge = a
```

必须进行显式类型转换：

```go
var b UserAge = UserAge(a)
```

完整修改：

```go
type UserAge int

func main() {
    var a int = 18
    var b UserAge = UserAge(a)

    fmt.Println(b)
}
```

> 注意：真正的类型别名写法是 `type UserAge = int`，这种情况下 `UserAge` 与 `int` 是同一个类型。

</details>

## 三、场景应用与改错题

### 9. 【场景改错题】

某新手工程师尝试编写一个 JSON 响应数据结构，代码如下：

```go
package main

import (
    "encoding/json"
    "fmt"
)

type UserResponse struct {
    userId   string
    userName string
    status   int
}

func main() {
    resp := UserResponse{
        userId:   "1001",
        userName: "Charlie",
        status:   1,
    }

    data, _ := json.Marshal(resp)
    fmt.Println(string(data))
}
```

运行后发现控制台输出为 `{}`，未能成功序列化字段。

请指出现象背后的原理并给出修改后的代码。

<details>
<summary>答案</summary>

#### 原理说明

Go 语言通过首字母大小写控制标识符的导出权限：

* 首字母大写：导出（Exported）
* 首字母小写：未导出（Unexported）

原代码中的：

```go
userId
userName
status
```

全部是小写开头，因此属于未导出字段。

`json.Marshal` 位于：

```go
encoding/json
```

包中，其内部通过反射机制读取结构体字段。

由于这些字段是未导出的，`encoding/json` 无法直接读取它们，因此最终没有可序列化的字段，输出：

```json
{}
```

#### 修改后的代码

```go
type UserResponse struct {
    UserId   string `json:"user_id"`
    UserName string `json:"user_name"`
    Status   int    `json:"status"`
}

func main() {
    resp := UserResponse{
        UserId:   "1001",
        UserName: "Charlie",
        Status:   1,
    }

    data, _ := json.Marshal(resp)
    fmt.Println(string(data))
}
```

输出：

```json
{"user_id":"1001","user_name":"Charlie","status":1}
```

这里：

```go
`json:"user_id"`
```

就是 Struct Tag，用于告诉 JSON 序列化器该字段对应的 JSON key。

</details>

### 10. 【场景设计题】

在物联网 SCADA 平台项目中，硬件节点上报的脚本触发器配置为 JSON 格式：

```json
{"type":"schedule", "interval_ms":1000, "watch_tags":["T1","T2"]}
```

请定义一个对应的 Go 结构体 `ScriptTrigger`，要求：

1. 字段能被 JSON 库正常序列化/反序列化；
2. JSON 中的字段 key 符合下划线命名规范，例如 `interval_ms`；
3. 当 `watch_tags` 为空时，允许在序列化时忽略该字段。

<details>
<summary>答案</summary>

```go
type ScriptTrigger struct {
    Type       string   `json:"type"`
    IntervalMs int      `json:"interval_ms"`
    WatchTags  []string `json:"watch_tags,omitempty"`
}
```

说明：

* 字段首字母大写，保证字段可被 JSON 包通过反射访问。
* `json:"type"` 指定 JSON 字段名称。
* `json:"interval_ms"` 将 Go 字段 `IntervalMs` 映射为 JSON 中的 `interval_ms`。
* `omitempty` 表示当 `WatchTags` 为零值时，在序列化时忽略该字段。

例如：

```go
trigger := ScriptTrigger{
    Type:       "schedule",
    IntervalMs: 1000,
}
```

序列化结果可以是：

```json
{"type":"schedule","interval_ms":1000}
```

</details>

### 11. 【代码编写题】

在处理业务数据时，经常需要从 `map[string]string` 中检索用户配置。

请利用 Go 语言 `if` 语句带初始化声明的语法，编写一段代码：

从 `userMeta` 中检索 Key 为 `"theme"` 的配置，若找到则打印主题名，若未找到则打印 `"使用默认主题"`。

<details>
<summary>答案</summary>

```go
userMeta := map[string]string{
    "theme": "dark",
    "lang":  "zh-CN",
}

if theme, exists := userMeta["theme"]; exists {
    fmt.Printf("找到配置，当前主题为: %s\n", theme)
} else {
    fmt.Println("使用默认主题")
}
```

这里：

```go
theme, exists := userMeta["theme"]
```

使用的是 Go 的 `map` **comma-ok** 模式。

其中：

* `theme`：取出的 value
* `exists`：表示 key 是否存在

同时还结合了 `if` 的初始化语句：

```go
if 初始化语句; 条件 {
}
```

这是 Go 中非常常见的写法。

</details>

### 12. 【性能与内存解析题】

比较以下两种坐标矩形结构体的内存占用与空间分布：

```go
type Point struct {
    X, Y int
}

// 结构体 A
type RectA struct {
    Min Point
    Max Point
}

// 结构体 B
type RectB struct {
    Min *Point
    Max *Point
}
```

请问：

在 64 位系统下，`RectA` 与 `RectB` 结构体变量本身在栈上占用的内存字节数分别是多少？

哪个对 CPU 缓存更友好？

<details>
<summary>答案</summary>

#### 1. RectA 的内存占用

64 位系统下：

```go
int = 8 字节
```

因此：

```go
Point = X + Y
      = 8 + 8
      = 16 字节
```

`RectA` 中包含两个 `Point`：

```text
RectA
├── Min.Point.X  8 bytes
├── Min.Point.Y  8 bytes
├── Max.Point.X  8 bytes
└── Max.Point.Y  8 bytes
```

因此：

```text
RectA = 16 × 2 = 32 字节
```

#### 2. RectB 的内存占用

`RectB` 中包含两个指针：

```go
Min *Point
Max *Point
```

64 位系统下，一个指针通常占：

```text
8 字节
```

所以：

```text
RectB = 8 + 8 = 16 字节
```

这里计算的是 **RectB 结构体本身**，不包括两个 `*Point` 所指向的 `Point` 数据。

#### 3. 哪个更缓存友好？

通常是：

```text
RectA
```

更缓存友好。

原因是 `RectA` 中的所有数据直接连续存储：

```text
[ Min.X ][ Min.Y ][ Max.X ][ Max.Y ]
```

CPU 访问时不需要先读取指针，再跳转到其他内存位置。

而 `RectB` 的结构类似：

```text
[ Min指针 ][ Max指针 ]
      ↓          ↓
   Point       Point
```

实际的 `Point` 数据可能位于内存中的其他位置，因此存在额外的指针追踪和缓存未命中的可能。

所以在需要频繁访问 `Min`、`Max` 数据的场景中：

```text
RectA 通常具有更好的局部性和缓存友好性。
```

</details>

## 四、综合拓展题

### 13. 关于 `json.Marshal(v)` 的返回值，下列说法正确的是（ ）

A. 直接返回 `string` 类型的 JSON 字符串

B. 返回 `([]byte, error)`，因此打印时通常需要使用 `string()` 强转

C. 若传入的 `v` 是结构体值类型而非指针，则无法完成序列化

D. 序列化时不会读取 Struct Tag，Tag 仅在反序列化（Unmarshal）时生效

<details>
<summary>答案</summary>

**正确答案：B**

`json.Marshal` 的函数签名是：

```go
func Marshal(v any) ([]byte, error)
```

因此返回：

```go
[]byte
error
```

例如：

```go
data, err := json.Marshal(user)
if err != nil {
    panic(err)
}

fmt.Println(string(data))
```

其中：

```go
string(data)
```

是将 JSON 字节切片转换成字符串，方便打印。

另外：

* 结构体值可以传给 `json.Marshal`
* 结构体指针也可以传给 `json.Marshal`
* Struct Tag 在序列化和反序列化过程中都可以发挥作用

例如：

```go
type User struct {
    Name string `json:"user_name"`
}
```

序列化：

```go
json.Marshal(User{Name: "Tom"})
```

可以得到：

```json
{"user_name":"Tom"}
```

</details>

### 15. 【问答题】

Go 语言没有 `class` 和 `extends`（继承），它是如何承载面向对象（OOP）编程思想中的“数据封装”与“多态/组合”关系的？

<details>
<summary>答案</summary>

#### 1. 数据封装

Go 使用 `struct` 组织数据字段：

```go
type User struct {
    Name string
    age  int
}
```

同时通过首字母大小写控制访问权限：

* 大写开头：导出，包外可访问
* 小写开头：未导出，包外不可直接访问

因此实现了基本的数据封装。

#### 2. 行为关联

Go 可以通过方法（Method）将行为绑定到结构体：

```go
type User struct {
    Name string
}

func (u User) SayHello() {
    fmt.Println("Hello", u.Name)
}
```

这样就实现了数据与行为的关联。

#### 3. 组合胜于继承

Go 没有传统意义上的：

```text
extends
```

而是通过结构体嵌套（Embedding）实现能力组合。

例如：

```go
type Animal struct {
    Name string
}

func (a Animal) Eat() {
    fmt.Println("eating")
}

type Dog struct {
    Animal
}
```

`Dog` 可以通过嵌入 `Animal` 获得相关字段和方法。

这种方式强调：

> Composition over Inheritance（组合优于继承）

避免了传统继承体系中的深层耦合。

#### 4. 多态

Go 通过 `interface` 实现多态。

例如：

```go
type Animal interface {
    Speak()
}
```

不同类型只要实现了 `Speak()` 方法，就自动满足该接口：

```go
type Dog struct{}

func (Dog) Speak() {
    fmt.Println("汪汪")
}

type Cat struct{}

func (Cat) Speak() {
    fmt.Println("喵喵")
}
```

于是：

```go
func MakeSound(a Animal) {
    a.Speak()
}
```

可以传入不同类型：

```go
MakeSound(Dog{})
MakeSound(Cat{})
```

这就是 Go 中典型的接口多态。

因此可以总结为：

```text
struct       → 数据组织
首字母大小写 → 数据封装
method       → 行为关联
embedding    → 组合复用
interface    → 多态
```

</details>
